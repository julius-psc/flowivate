Currently, Flowivate is a productivity / discipline dashboard web app that's goal is to help users track different metrics and be more productive. Essentially it is an empty dashboard where users can add features that they like and would find useful for their use-case. So before that, the target users are students, solopreneurs and anyone who wants to be more productive. The features can be dragged around the main dashboard view to the user's liking. Features include Pomodoro, Deep work where the user chooses a task, ambient sounds, task tracking, journalling, meditation, water / sleep / mood tracking. The design is very modern and sleek. 

The issue : the rise of vibecoding and creation of dashboards for anything and everything in 2026. AI has taken over the world and thousands of people are shipping productivity dashboards (although not always good quality) as web applications as they have become extremely easy to build and ship. I feel like Flowivate, in its current state, uses AI way too simply and doesn't use it to its max potential. Indeed it just has a chatbot and basic AI parsing / dividing of tasks with a daily recap that doesn't fully work and doesn't feel personalized at all. From returns i have got, people say that they want a mobile application of this and that they feel like they would only use 1/2 features of the app but that's it. So, basically 99.9% churn rate because no one would use the full application to its full extent. The issue here is trying to make it an all-in-one application with features that are way too diverse for too many different profiles instead of narrowing it down and niching hard. Granted, the all-in-one was my moat however I am sure there are different ways to portray this effect. And for the mobile application, i feel like transitioning 100% to that is a not a good idea as the market is very saturated in that niche with applications that are very good. 

The solution : I have a very vague but precise idea of what i want to build. With the raise of AI has come agentic AI as well as MCPs (unsure of this yet). Devs are spending hours building agents for their different needs such as coding, marketing, ==productivity==, etc. What i find interesting are the productivity agents. I feel like Flowivate could be turned into an agent that lives on the user's Macbook / Mac that COMMUNICATES, if the user has one, with their iPhone. So I am thinking some sort of Raycast but for focus and productivity. The dashboard would be minimized to some sort of minimalist command centre where the user can track their metrics and monitor their agent, some sort of Jarvis but for productivity and ==wellbeing==. DIfferent things the agent could do : 
- Track app / website usage via the Apple API like https://rize.io/ + nudge users when too much on an application
- Grow agent's context memory as time goes living on the user's computer / (phone too ?) and learning from how they use their phone 
- Give helpful insights each week on how the user uses their devices and how to improve
These features are similar to what Rise has to offer
I really find what Glaze by Raycast has to offer really really good and if i could bring my own twist to it, would be a key differentiator. Indeed, Glaze is an INTERNAL app builder that follows raycast's design system and builds apps FOR the user that they can then publish to the public or keep as their own local tool on their macbook and has access. So if somehow i could implement that but for Flowivate and making only productivity / discipline mini-tools where the agent has access and can make decisions, advise, etc, that would be a pivotal move for Flowivate and definitely make me stand out. I feel like Flowivate would have to live on the menubar and be triggered by a command just like Raycast. 
The thing is i don't want it to be an all-sense productivity tool that has access to 50 different integrations like Slack, Notion, etc because a lot of agents being built today do that exact thing and I want my application to be niche to productivity-driven users. If during the onboarding process the agent actually got to know the user and what his goals are, but not just a static if / else, actually feeding it to the agent for reasoning, it would be a great way to personalize the agent to the user's need. I feel like the dashboard that i built should be kept but minimized as i mentioned before. I feel like aesthetics and making onboarding and the UX are super important in this project to really stand out from the 30 second Lovable prompt. I am unsure of what else I could bring to this app to make it stand out from other existing solutions. For the deep work mode, the user would choose the task and sound that they want to play in the background and then an overlay would appear with a timer if wanted allowing the user to focus. Although that is just a tiny feature I am thinking of implementing. Features like journalling and book logging could definitely be kept as they bring valuable insight. 
Now to talk about the mobile aspect, I really like the design of modern, clean widgets. If somehow syncing the mobile and the desktop for those who have them, it would be really useful. The computer would be the main powerhouse. Although, in its first state and until thorough product validation through loyal paying users and high long-term retention rate, I feel like a mobile app is unnecessary and overkill. Widgets can easily be displayed on the main desktop view so I feel like focusing on just that is a good idea in the first quarter of production.
